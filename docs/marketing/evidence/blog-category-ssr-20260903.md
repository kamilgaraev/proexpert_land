# Категории блога: серверный HTML и загрузка данных

Дата: 3 сентября 2026. Ветка: `feat/marketing-bridge-redesign-20260902`. Код подготовлен локально, без коммита и развёртывания этим исполнителем.

## Исправлено

- `onBeforeRender` распознаёт `/blog/category/:slug`, получает валидный каталог, выбирает активную категорию и загружает первую страницу опубликованных материалов по её ID.
- Начальные данные проходят `pageProps → CatchAllPage → App → BlogCategoryPage`. Название категории и ссылки на статьи присутствуют в серверном HTML, до выполнения JavaScript.
- `getBlogCategorySeo` формирует одинаковые title, description, canonical и robots-настройки на сервере и клиенте. Берутся метаданные категории; при их отсутствии используются название и описание.
- Несуществующая категория после успешного валидного каталога получает HTTP 404, noindex и видимый заголовок «Категория не найдена». Ошибка сети, HTTP 503 и повреждённый ответ API не трактуются как отсутствие категории.
- Успешные начальные данные не запрашиваются повторно при гидратации. При частичном результате повторяется только недостающий запрос. Сайдбар получает уже загруженные категории.
- При смене slug содержимое категории перемонтируется с новым ключом. Поздний ответ предыдущей страницы не меняет новую страницу. Повторный клик загрузки следующей страницы защищён флагом; одинаковые ID не дублируются.
- В `blogPublicApi.getCategories` добавлена проверка успешности и формы ответа: API больше не превращает `success:false` или повреждённую коллекцию в пустой каталог.

## Границы блока / передача следующему этапу

Внешний вид категории существенно не изменён. Общий блог остаётся за пределами `LandingLayout` в App, а `BlogPublicLayout` самостоятельно выводит Navbar/Footer в белой обёртке без `.most-marketing`. Это известная причина визуальной несогласованности; root исправляет её следующим блоком. Не следует просто переносить маршруты внутрь LandingLayout с сохранением собственного Navbar/Footer: получится дублирование.

На сервере каждый запрос имеет существующий ограниченный timeout; каталог и статьи получаются последовательно, поскольку ID категории нужен для второго запроса. Полный сбой каталога пока сохраняет HTTP 200 с возможностью загрузки в браузере, как существующий блог; ложный HTTP 404 не отдаётся.

После объединения визуального блока нужны проверка конечного HTML и интерфейса на опубликованном сайте. Производственная проверка и выпуск этим исполнителем не выполнялись.
