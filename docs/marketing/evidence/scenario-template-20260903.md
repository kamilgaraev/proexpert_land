- Повторяющий список операций помещён в native details с его настоящим заголовком; основные сведения о ролях остаются видимыми. Текст сохранён в DOM.
- Hero CTA ведёт на уникальный #contact-form непосредственно к форме; старый #contact сохранён. На /foreman-software при 390 px после полной стабилизации formTop=160.7, firstInputTop=356.8 при высоте окна844, overflow=0; поля видны сразу.

- После поведенческой правки повторены только целевые ESLint, Prettier и SeoClusterPage.test.tsx: PASS, 4 теста. Gortex detect_changes и guards выполнены; guard rules отсутствуют.
- Обновлённые снимки четырёх URL при 390/1440: `output/playwright/scenarios/*-workflow-review.png` и `*-390-cta-review.png`. Проверены лично foreman1440 workflow и foreman390 CTA; переданы reviewer для узкого повторного просмотра. Эти снимки приоритетнее предыдущих full-final для изменённых секций.

## Что изменено

Файлы исполнения: `src/pages/landing/SeoClusterPage.tsx` и новый `src/styles/marketing-scenarios.css`. Общие CSS, MarketingPrimitives, ContactForm и данные страниц не изменялись этим исполнителем.

- Hero содержит поисковой H1, описание, существующие CTA и одну предметную сцену того же здания. `supportingQueries` остаются в данных для SEO, но больше не показаны как рекламные плашки.
- Иллюстрация выбирает фундамент/материал для снабжения и оценки, завершённый объект для ПТО/документов, каркас для остальных сценариев. На странице только одна сцена; она декоративная, с пустым alt и `aria-hidden`, не выдаётся за экран программы или подтверждение возможности.
- Контекст объединяет людей и исходные задачи в две спокойные колонки. Удалены повторяющиеся выдуманные fallback-блоки «подходит / осторожно / старт», которые повторяли аудитории, проблемы и контактные пункты. Настоящий optional trust из данных сохраняется.
- Подтверждённый workflow показан одной оранжевой последовательностью. На desktop количество колонок равно количеству этапов; четыре этапа не распадаются на 3+1. До 1280 px последовательность вертикальная, до 1080 px описание располагается под заголовком этапа.
- Свойства процесса показаны строками, без числовых обещаний и карточек метрик. Возможности и роли используют текущие данные страницы.
- Условия из FAQ сохранены вместе с прежней генерацией schema по тем же данным. В шаблоне FAQ заменён на нативные details/summary: клавиатура работает без дополнительного JS, плюс — SVG, всё содержание присутствует в HTML.
- Контактная форма использует действующий класс дизайн-системы `most-contact-form`: общий фон, поля и кнопка с радиусом 4 px, читаемые SVG, без скрытия формы на входной анимации. Не менялись сеть, валидация и отправка.
- Связанные решения и статьи оформлены компактными ссылками. Все существующие IDs `audience`, `problems`, `trust`, `process-comparison`, `workflow` при наличии данных, `automation`, `faq`, `contact` сохранены.
- Все размеры текста берутся из `--most-type-*`; общий контейнер сохраняет отступы 48/32/20 px. CSS ограничен классами сценарного шаблона. Движение — короткий отклик стрелки ссылки и значка раскрытия, без появления всех секций. Reduced motion отключает переходы.

## Визуальный просмотр и исправления

Просмотрены реальные hero, полные страницы, workflow и контактная форма. После первого прохода исправлены белые округлые панели FAQ, прежняя округлая форма, исчезновение формы на начальной анимации и слишком узкий столбец заголовков этапов при тексте 200%.

Съёмка полного документа после прокрутки иногда теряет masked-изображение за пределами viewport. Кроме того, стандартное скрытие caret во время снимка могло попасть в процесс гидратации и вызвать предупреждение о добавленном `caret-color`. Финальные снимки сделаны с начала страницы, `caret: initial`, после завершения входа. Повторная контрольная съёмка: console errors 0, герой и форма видимы. Это исправление метода проверки, не маскировка дефекта CSS сайта.

## Границы готовности

Этот блок изменяет общий визуальный шаблон сценариев, не подтверждает автоматически все продуктовые заявления. Root параллельно сверяет и обновляет данные страниц и метаданные. После объединения актуальных данных требуется независимое UI-ревью и контроль опубликованных страниц. Наличие зелёных проверок не означает оценку 10/10 или завершение всей цели.
