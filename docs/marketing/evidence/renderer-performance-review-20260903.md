## Первоначальное замечание — закрыто

Ниже сохранены исходная причина и доказательство до исправления; номера строк относятся к той версии.

### P2 — ошибка React до commit блокировала следующие переходы

Место: `src/renderer/_default.page.client.tsx:37–39` (создание `pendingCommit`), `:29` и `:60` (ожидание), `ClientCommit` `:22` (единственный путь завершения).

Новый `pendingCommit` завершается только эффектом `ClientCommit`. Если `Page` или другая часть дерева бросает ошибку до успешного commit вне локального `AppErrorBoundary`, React очищает корень и эффект `ClientCommit` не выполняется. Для первоначальной главной путь `index.page → MarketingShell → LandingPage` не содержит AppErrorBoundary общего App. Тогда текущий `render()` остаётся незавершённым, а любой следующий вызов тоже останавливается на `await pendingCommit`. Обычная ошибка одного экрана превращается в невозможность восстановиться переходом на другой экран.

Подтверждение: отдельный read-only probe на установленных React и jsdom воспроизвёл `createRoot → ClientCommit(useEffect) → throwing child`: результат `uncaughtErrors=1`, `commitEffectRan=false`, `containerEmpty=true`. Исходники не модифицировались. В пяти клиентских тестах react-dom замокан, commit вызывается самим тестовым mock; отказ React до commit не проверяется.

Исправление: гарантированно освобождать/завершать ожидание при синхронном отказе root API и при необработанной ошибке React, либо поставить внешний boundary, который гарантирует commit человекочитаемого состояния ошибки. Не подавлять ошибку молча. Регрессия: первый экран падает до commit, затем новый публичный экран успешно рендерится в тот же контейнер; не остаётся незавершённого ожидания. После исправления достаточно проверки этой ветки и существующего узкого client renderer набора.

## Подтверждённые свойства остальных ветвей

- PageShell не содержит статических импортов AuthProvider/PermissionsProvider; они изолированы в PrivatePageShell. Loader содержит динамический import, кеширует компонент и объединяет одновременные обращения.
- Подготовка приватного wrapper ожидается до `renderToString` на сервере и до начального hydrate на клиенте. Server singleton кеширует тип компонента, а не экземпляр пользовательской сессии.
- `useLocation` делает public/private ветку реактивной к текущему React Router pathname. Приватные children не монтируются до появления providers. Cleanup защищает от позднего обновления после ухода с маршрута; повтор сбрасывает локальное сообщение ошибки, loader сбрасывает отклонённый pending Promise.
- Cached Root устраняет повторный `hydrateRoot`. Первая навигация без hydration использует createRoot. Проверка поколения после ожиданий отбрасывает старый успешно разрешившийся import.
- BrowserRouter key включает `urlOriginal`, поэтому обновляется на Vike-навигации с query. Это осознанный remount дочернего дерева; сборка ЛК через main.tsx не использует этот renderer. Для приватного SSR remount означает повторный bootstrap providers, как оговорено при выборе решения.
- `fonts.css` содержит локальные декларации IBM Plex Sans и Mono, `font-display: swap`, unicode-range; Mono сохранён для кода в статьях и экранов ЛК. В CSS 21 ссылка WOFF2: 6 Sans и 15 Mono. Проверка двоичных таблиц/glyph coverage и лицензии не выполнялась этим reviewer; наличие/поставка файлов относится к проверкам автора блока.

## Проверки и пределы

Результаты автора блока: 16 целевых тестов shell/auth/router и 5 client renderer тестов проходят; ESLint проходит; три ранних перехода contractors → contact и переход home → login не дали browser pageerrors. Ревьюер прочитал тесты, но не повторял уже успешные наборы.

Gortex `detect_changes` выполнен; он не включает untracked файлы, поэтому новые файлы дополнительно прочитаны явно через `read_file`. `get_test_targets` нашёл три новых тестовых файла, прямой тест server render не найден. `check_guards`: правила не настроены. Во время первоначального ревью детерминированный `review(scope=unstaged)` не завершился за внутренний лимит 59 секунд; его положительный вердикт тогда не заявлялся. После восстановления интеграции автор сообщил об успешном Gortex-review 44 файлов за 1,3 секунды с нулём findings; этот запуск ревьюер не повторял. Обновление данного отчёта после восстановления выполнено через Gortex с подтверждением `disk_verified=true`, `graph_status=fresh`.

Документация React/Vike перед оценкой новых ветвей проверена через Context7: `renderToString` не ждёт lazy/Suspense; `hydrateRoot` используется только для первого SSR-дерева; преждевременный root.render завершает hydration переходом на клиентский рендер.

Ревью исходники не меняло. Создан только этот evidence-документ.
