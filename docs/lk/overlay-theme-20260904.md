# Общая тема всплывающих элементов ЛК

Проблема воспроизведена на форме поддержки: Select переносит содержимое в Portal под body. CSS-переменные, заданные только на .most-workspace, туда не наследуются. Появляются старые голубые выделения, мелкий текст и низкие пункты.

Решение: одна тема на .most-workspace и body:has(.most-workspace). Общие правила типографики, полей, фокуса и reduced-motion действуют также на порталы открытого ЛК. При отсутствии контейнера ЛК область не активна, дополнительных глобальных классов и JavaScript-эффектов очистки не требуется. Добавлены --popover/--popover-foreground. Именованные роли option/menuitem/menuitemcheckbox/menuitemradio получают высоту44px, текст16px и SVG20px. Combobox получает общую высоту поля44px.

Состояние, права, размещение порталов и управление фокусом Radix не менялись. Не добавлялся собственный обработчик клавиатуры. Важная граница: CSS :has требует современный браузер; проверить CSS.supports в целевом встроенном Chromium. Отдельного доказательства Safari/Firefox пока нет.

Проверки до выпуска: PostCSS успешно разобрал39 узлов, git diff --check PASS, Gortex staged review APPROVE без замечаний. Бизнес-тесты не повторялись: меняется только CSS. Выпуск 33831823221 (358dbd70, target=lk) завершился успешно. Production проверен в собственной скрытой вкладке: на 390 px пункты Select имеют высоту 44 px и текст 16 px, выбранный пункт нейтрального цвета; Escape закрывает список и возвращает фокус на combobox. На 1440 px меню профиля содержит пункты 44 px/16 px, без горизонтального переполнения. Диалог добавления администратора проверен на 768 px: поля 52 px/16 px, роли загрузились, окно закрыто отменой без отправки данных. CSS.supports подтверждает поддержку :has в проверенном Chromium. На главной маркетинга в новой собственной скрытой вкладке подтверждено: контейнера .most-workspace нет, body не соответствует селектору темы ЛК. Заголовок главной сохранился. Это проверка изоляции темы, а не повтор полного маркетингового аудита.
