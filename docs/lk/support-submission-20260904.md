# Поддержка: достоверный результат отправки

Подтверждён дефект: `supportService.submitSupportRequest` возвращает status/data и не выбрасывает ошибку HTTP. ContactForm без проверки показывал успех и очищал поля даже при 400/422/429/500. Регрессионный тест до исправления показал блок успеха при ответе 500.

Исправлено в форме: проверяются статус 2xx и success!==false; при отказе сохраняется черновик, возвращается доступная кнопка отправки. Сетевые/JSON исключения не выводятся сырым текстом. 422 и 429 имеют понятные сообщения. Успех размечен role=status, ошибка role=alert. Ограничения темы255 и сообщения5000 согласованы с StoreSupportRequest backend. API/payload и backend не менялись.

Проверки: Vitest7 PASS (HTTP200 success=false,400,422,429,500; принятый200; сетевой отказ), ESLint2файла PASS. Gortex review: 0 замечаний правил, MEDIUM риск; граф не связал покрытие, фактические тесты ContactForm.test.tsx выполнены. Реальные письма не отправлялись. Локальная сборка не запускалась.

Согласован контракт отправителя: backend SupportController берёт имя/почту авторизованного пользователя. Форма теперь показывает эти данные из useAuth и не предлагает менять адрес, который сервер всё равно проигнорирует. Подпись сообщает об ответе на почту аккаунта. Для гостевого состояния остаются вводимые поля. Дополнительный тест проверяет readOnly и передаваемый адрес аккаунта. Итого 8 тестов PASS, ESLint PASS, TypeScript --noEmit PASS после удаления неподдерживаемой опции exact в тестовых селекторах. Серверная маршрутизация писем не менялась.
