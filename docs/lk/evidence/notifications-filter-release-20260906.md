## Изменения

После чтения, удаления и массовой отметки страница получает актуальный серверный снимок. Фильтр непрочитанных не сохраняет уже прочитанную запись. Пустая последняя страница переключается на существующую. Счётчик непрочитанных берётся из общего серверного итога, а не из текущих 15 записей. Массовая отметка защищена от повторного нажатия; новые уведомления после границы серверной операции остаются непрочитанными. Если обновление после удаления не удалось, удалённая запись не возвращается, доступен повтор загрузки.

## Оставшаяся часть B03

Переход от уведомления к договору ещё не реализован. В admin существует /contracts/:contractId, но этот маршрут использует текущий выбранный проект. Поэтому он не гарантирует правильный объект. Полный маршрут /projects/:projectId/contracts/:contractId требует проверенного projectId из серверных данных. Исторические уведомления содержат contract.id, но не projectId; исправление только новых событий недостаточно. При реализации учитывать существующий ContractAccessService, принадлежность организации, права, удалённые и многопроектные договоры, пакетную загрузку без N+1. Не подставлять текущий проект пользователя и не использовать произвольный URL из уведомления.

Повторная браузерная проверка до выпуска: фильтр прочитанных загрузил одну запись и оставался корректным после завершения запроса; непрочитанные показывали нулевой итог и пустое состояние. Ранее наблюдавшаяся ошибка прочитанных сейчас не воспроизвелась; постоянный дефект серверного фильтра не доказан. Реальные уведомления не изменялись.
