## Как ставить галочки

- `[x]` — выполнен именно указанный сценарий, есть подтверждение ниже или в реестре выпусков. `[ ]` — требуется работа или доказательство; это не обязательно отсутствующий функционал.
- Для закрытия открытого пункта записать дату, точный маршрут/сценарий, ширину экрана, результат, путь к тесту/снимку или номер PR и CI. Для визуальной проверки одного зелёного теста недостаточно.
- Если внутри пункта перечислено несколько действий, нужны все перечисленные действия. Найденный дефект остаётся внутри того же пункта до исправления и проверки выпуска.
- Проверки без изменений покрываемого кода повторять не нужно. По завершении блока выполнить один релевантный набор проверок, одно независимое ревью существенного кода и штатный выпуск.
- Браузер только собственный встроенный. Данные тестового аккаунта не публиковать. Не отправлять реальные приглашения/заявки, не менять права коллег и не проводить платежи ради приёмки. Для опасных/недоступных ветвей использовать изолированные тесты с точным указанием границы.
- Цель закрывается после всех пунктов A–H и итогового отчёта. Внешние ограничения из раздела I не выдавать за выполненную проверку. Новые пожелания не добавлять незаметно: в список добавляются только обнаруженные дефекты исходного объёма с причиной.
