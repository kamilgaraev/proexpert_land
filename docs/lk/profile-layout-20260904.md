# Профиль: адаптивная форма

В production на ширине 390 px воспроизведено обрезание кнопки «Сохранить»: заголовок и обе кнопки располагались в одной строке внутри контейнера с overflow-hidden. На странице также сохранялись градиентные жёлтые поверхности и тяжёлые тени.

Исправление: заголовок и действия располагаются вертикально до широкого экрана, кнопки переносятся при необходимости. Внешний блок больше не обрезает содержимое. На телефоне внутренний отступ 20 px, на большем экране 32 px. Панели нейтральные с тонкой границей, основные действия используют общий оранжевый акцент. Email и статус подтверждения допускают перенос. Иконки полей и действий 20 px; действия не ниже 44 px. Подписи четырёх полей связаны с input через htmlFor/id; добавлены стандартные autocomplete и доступное имя загрузки аватара.

Обработчики сохранения, отмены и API-контракт в этом блоке не менялись. Проверки: ESLint изменённого файла и git diff --check прошли. Бизнес-тесты для изменений только разметки не запускались. Выпуск a35476b0 через CI 33832579232 target=lk завершился успешно. В собственной вкладке production проверены 390 и 320 px: обе кнопки доступны, на 320 px переносятся, горизонтального переполнения нет. Изменение имени в черновике → Отмена → Редактировать восстановило исходное имя, запрос сохранения не отправлялся. На 768 px обнаружена тесная двухколоночная форма из-за боковой навигации. Порог обеих сеток изменён с md на xl; эта дополнительная правка пока локальная, требует проверки и следующего выпуска. Проверка 1440 px последнего профиля ещё не выполнена.

Функциональное замечание исправлено: _method добавляется после проверки изменений. Пустая форма не отправляет запрос. Добавлены четыре компонентных регрессионных теста: отсутствие запроса без изменений, восстановление при отмене, состав PATCH-запроса, сохранение черновика при ошибке. Все четыре прошли, ESLint и TypeScript --noEmit прошли. Анимация подменена только в компонентных тестах из-за AbortError в happy-dom при размонтировании; поведение анимации этими тестами не проверяется. Gortex review не нашёл замечаний, но сообщил MEDIUM по графовой оценке покрытия; фактический компонентный прогон выполнен отдельно. До исправления не считать отсутствие лишних запросов доказанным. userService.updateProfile (src/utils/api.ts:657) прочитан: проверяет response.ok, на ошибке выбрасывает ApiRequestError со status/errors. Проблемы безусловного успеха, найденной ранее в форме поддержки, здесь нет. Следующий функциональный блок ограничить отсутствием лишнего запроса при неизменённой форме и регрессией отмены/ошибки; не переписывать общий API-сервис.
