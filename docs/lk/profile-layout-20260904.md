# Профиль: адаптивная форма

В production на ширине 390 px воспроизведено обрезание кнопки «Сохранить»: заголовок и обе кнопки располагались в одной строке внутри контейнера с overflow-hidden. На странице также сохранялись градиентные жёлтые поверхности и тяжёлые тени.

Исправление: заголовок и действия располагаются вертикально до широкого экрана, кнопки переносятся при необходимости. Внешний блок больше не обрезает содержимое. На телефоне внутренний отступ 20 px, на большем экране 32 px. Панели нейтральные с тонкой границей, основные действия используют общий оранжевый акцент. Email и статус подтверждения допускают перенос. Иконки полей и действий 20 px; действия не ниже 44 px. Подписи четырёх полей связаны с input через htmlFor/id; добавлены стандартные autocomplete и доступное имя загрузки аватара.

Обработчики сохранения, отмены и API-контракт в этом блоке не менялись. Проверки: ESLint изменённого файла и git diff --check прошли. Бизнес-тесты для изменений только разметки не запускались. После выпуска требуется визуальная проверка 320/390/768/desktop и отмена несохранённого черновика без записи в аккаунт.

Отдельное найденное замечание для следующего функционального блока: hasChanges проверяется после добавления _method, поэтому всегда true. До исправления не считать отсутствие лишних запросов доказанным. Также проверить, как userService.updateProfile обрабатывает HTTP-ошибки, прежде чем менять обработчик.
