# Проверки и выпуск сайта МОСТ

Изменения проходят через PR в `main`. GitHub требует «Проверки по изменению», статус `most/release-admission` и разрешение всех обсуждений. После нового коммита требуется завершённый Codex Review его полного head SHA.

Документация в `docs/*.md` и инструкции разработки проходят короткую проверку без установки Node.js. После слияния только таких файлов production-сборки не запускаются. Изменение общих исходников затрагивает сайт и личный кабинет.

Если статус допуска красный, откройте соответствующий run. Проверьте head SHA, результат проверок PR и открытые обсуждения. После устранения причины можно повторить workflow «Допуск PR» из `main`, указав номер PR. Недоступность GitHub или runner оставляет выпуск заблокированным.

После squash merge workflow выпуска повторно проверяет происхождение ревизии и допуск. Для ручного запуска выберите `main` и требуемую цель. Параметры восстановления резервной копии предназначены для штатного восстановления соответствующего сайта.

Публичные PR обрабатывает стандартный GitHub-hosted Linux runner. Для этого репозитория запуск службы на рабочем ПК не требуется.
